# Portal administrativo del manual (`portal/`)

Estado al 2026-11-25. Alcance pedido por la persona usuaria: panel para crear, editar, ordenar y publicar el manual **sin tocar código**,
con PostgreSQL como fuente de verdad, ajustes, actualización desde Git y respaldo descargable. Detalle técnico: `portal/CONTRACT.md`
(contrato y adendas), `portal/README.md` (uso) y `portal/web/DESIGN.md` (diseño y componentes).

## Cómo funciona
- Contenido en PostgreSQL (`ispmax_manual`; pruebas en `ispmax_manual_test`, que las pruebas vacían). Clave solo en `portal/.env` (ignorado por Git).
- **Guardar = en vivo; Publicar = solo lo nuevo** (decisión 2026-11-25). Guardar algo ya publicado reconstruye el manual solo (espera 8 s, sin builds paralelos, ~35 s). Una página nueva nace en borrador y se publica a mano (cabecera o pantalla Borradores). El indicador del sitio está en la barra superior; pantalla **Sistema** con el estado del manual.
- Reconstrucción: exportar BD → `.mdx` y assets en `portal/work/site/` → `npm run build` → `portal/data/site/`, servido en `/manual/` (ajuste `site_base`; en producción `/`, con Nginx sirviendo ese volumen: **pendiente, regla 12**).
- **Git es solo para actualizar el código del sistema** (botón en Sistema: `fetch` + `merge --ff-only`, `npm ci` donde cambió, migrate, recompilar interfaz y manual, reinicio). El contenido NO se importa desde Git: manda la BD. No hace falta "exportar al repositorio".
- Las portadas de sección (`generado: true`, p. ej. `/tareas`) no son editables: las regenera `build-nav`.
- Cargar el contenido en una BD: paquete `.ispmax` (`npm run content:import`); `npm run setup` solo aplica el esquema. Ida y vuelta BD↔archivos: `npm run roundtrip` (0 diferencias en 285 páginas, 270 assets, 3 archivos de apoyo).

## Piezas
- `server/` Fastify: `routes/` (páginas, estructura anidada, assets, ajustes, usuarios, auditoría, tours), `sync/` (importar/exportar), `ops/` (publicar, Git, respaldos).
- `web/` React + Vite + **Tailwind v4** + Radix (librería en `src/components/ui`). Espacio de contenido tipo docs: árbol = menú real del manual (prueba automática contra `docs/_nav.json`), editor **por bloques** (`src/lib/blocks`: 285/285 páginas sin pérdida), tours (`features/tours`).
- Cambios en el manual (solo añadidos, nada visible hasta usarlos): `scripts/build-nav.mjs` (frontmatter `padre:` para subsecciones; sin `padre` el menú queda idéntico), `src/components/Tour.tsx` + bloque `isp-tour` en `styles/index.css` + registro en `rspress.config.ts` (`<Tour id="slug" />`; el JSON sale en `assets/tours/`).

## Paquete de contenido portable (`.ispmax`) y llevar el manual a otro sistema (2026-11-25)
- El contenido vive en PostgreSQL; el repo (`docs/`, `assets/`) es solo el origen histórico. Para desplegar en otro sitio: cargar un **paquete `.ispmax`** (gzip de JSON con páginas, imágenes, tours, estructura, subsecciones, redirecciones, borradores y ajustes de contenido; sin usuarios, sesiones ni ajustes de entorno; checksum sha256).
- Crear: pantalla **Respaldos → Respaldo del contenido**, o `npm run content:export` (desde `portal/`; guarda en `portal/data/backups/content/`, carpeta ignorada por Git). Cargar: misma pantalla, la tarjeta del Inicio en un sistema vacío, o `npm run content:import -- archivo.ispmax [--merge] [--yes]`. Reemplazar sobre contenido existente exige escribir CARGAR y crea antes un paquete de seguridad.
- Prueba de aceptación (`portal/test/content.test.mjs`): exportar → vaciar → importar → exportar a archivos = repo con 0 diferencias (558 archivos).
- Distinto del respaldo `pg_dump` (`.dump`, pantalla Respaldos → copia completa): ese incluye usuarios y sesiones y solo sirve en el mismo sistema. `backups.kind` distingue `db` de `content`.
- **Guardar el `.ispmax` FUERA de la carpeta del proyecto** (nube o disco): `portal/data/` no se versiona. Cuidado al limpiar esa carpeta en pruebas: un agente borró una vez el paquete real (se regeneró con `content:export`).
- `node server/dev-test-server.mjs <puerto>` admite `PORTAL_TEST_DB_NAME=<nombre>` para una base de pruebas propia (se crea, migra e importa el repo) y no chocar con la compartida.
