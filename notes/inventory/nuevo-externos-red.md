## EXT-165 · Qué configura ISPMAX en el MikroTik al guardar

- **Detalle (todo ✅ en `BE:common/utils/mikrotik.service.ts`):**
  - `cleanupSSLConfiguration` (`:386-495`): borra las reglas de `/ip/firewall/filter` cuyo comentario contenga «ISPMAX» (sin distinguir mayúsculas); `/ip/service/set numbers=www-ssl disabled=yes certificate=none port=443 address=`; `/ip/service/set numbers=api address=`; borra los certificados cuyo nombre contenga `ispmax` (si no puede, `trusted=no disabled=yes`). Todos los errores se ignoran.
  - `checkRouterAccessible` (`:115-145`): `/system/resource/print`; sin NAT: `/ip/service/set numbers=api port=<puerto_api> address=<IP pública del servidor> disabled=no`; con NAT: `address=` vacío y `disabled=no` (no toca el puerto).
  - `getServerPublicIP` (`:150-188`): `https://api.ipify.org?format=json`, `https://ifconfig.me/ip`, `https://icanhazip.com` (5 s cada una); error «No se pudo determinar la IP del servidor».
  - `configureSSL` (`:210-384`): si `https://<ip>:<sslPort>/rest/system/resource` ya responde (también con 401/403) devuelve «REST API SSL ya estaba configurado»; si no: `/certificate/add name=ispmax common-name=isp-max.net key-usage=key-cert-sign,crl-sign days-valid=3650`, espera 4 s, `/certificate/sign … ca-crl-host=ssl.isp-max.net`, espera hasta 10×2 s a `authority=true` y `trusted=true` («El certificado ispmax no completó el proceso de firma»); `/ip/service/set numbers=www-ssl certificate=ispmax port=<sslPort> address=<IP|vacío> disabled=no`; borra reglas con comentario «Acepta REST API SSL-ISPMAX» o «Acepta RouterOS API-ISPMAX» y crea ambas (`chain=input action=accept protocol=tcp dst-port=<sslPort|puerto_api>`, `src-address=<IP>` solo sin NAT, `place-before=0`); verifica el REST a los 3 s. Errores envueltos como «Error configurando SSL: …».
  - `configureFirewallApi` (v6, `:507-551`): crea solo «Acepta RouterOS API-ISPMAX»; error «No se pudo configurar el firewall del API: …».
- **Auto-reparación v7:** ✅ tras 2 fallos seguidos el monitor llama a `configurarRouterSSL` una vez por caída (`BE:router/router-monitor.service.ts:206-222`); v6 no se repara.
- **Orden:** ISPMAX crea sus reglas de firewall **después** de conectarse, por lo que el primer acceso debe estar permitido por la red del ISP.

## EXT-167 · Detrás de NAT

- **Código:** ✅ el interruptor viaja como `detras_nat`; con él activo no se limita por `address`/`src-address` el servicio `api`, `www-ssl` y las reglas de firewall de ISPMAX; el Puerto SSL **sí** se aplica y el Puerto API **no** se cambia (`BE:common/utils/mikrotik.service.ts:115-145,291-347,507-551`). Tooltip: «Actívalo si el RouterOS está detrás de NAT: no se restringe por IP en servicios ni firewall, porque tras el NAT la IP de origen no coincide. [El Puerto SSL sí se aplica al router.]» (`FormRouter.vue:793-800`). Comentario del código: «En modo NAT/Docker no restringimos … (la IP de origen no coincide con la IP pública del server tras pasar por el NAT)».
- **Recuperación:** ✅ si el servicio `api` quedó limitado a una IP equivocada, hace falta vaciar su lista de direcciones desde el router (`/ip service set api address=""`, equivalente a lo que ISPMAX escribe con NAT) y editar el router con «Detrás de NAT» habilitado. La ayuda de MikroTik documenta `address` como nombre antiguo de `available-from` y que una lista vacía permite cualquier dirección.
- **Pendiente de validar:** ❓ casos reales de red (VPN, Docker, doble NAT).

## Hallazgos del dominio

- Los campos de dominio y API key de SmartOLT no tienen etiqueta (solo `placeholder`), lo que impide saber qué campo es cuál una vez escrito.
- El banner de credenciales y el botón «Guardar» consideran válidos los valores de ejemplo (`https://tudominio.com`, `TuApiKey`, `tusubdominio`); solo el menú los distingue.
- La lista de OLT de SmartOLT (1 h) no se invalida al cambiar las credenciales.
- Si una respuesta de SmartOLT llega sin la clave `response` (por ejemplo un error entregado como 200 con `status: false`), la pantalla no avisa.
- AdminOLT: los errores de subdominio inexistente se silencian en las listas (`esErrorCredencialesAdminOLT`).
- `FormRouter`: `ip_host` es `varchar(18)`; el mensaje del spinner «Preparando router...» nunca se muestra porque `useRouter.js:113` compara `formRouter.registro_trafico` sin `.value` (queda «Procesando...»).
- `cleanupSSLConfiguration` se ejecuta también para v6 y deja `www-ssl` deshabilitado.
